# 世界历史九年级上册 · 历史学习网页（v2）

一个**纯框架**的历史学习应用：不含任何具体历史内容（内容由你自己添加/导入）。
包含四个互相切换的页面：

- **主页**（`index.html`）：空主页（预留占位）+ 侧边栏导航。
- **时间轴**（`timeline.html`）：理清世界古代史的时间线与不同文明/区域的先后关系，支持**多时间轴文档**标签卡切换。
- **问答练习**（`qa.html`）：导入 Markdown 文档自动拆成「单元 → 题目 → 答案」，先看题后看答案、星标薄弱点、多文档标签卡、分页、导出离线网页。
- **速查**（`quickref.html`）：从**地点 / 人物**逆向找出相关事件并记忆，可选多个时间轴为来源，支持「信息一览」与「主动学习」两种模式、星标薄弱点、打印 PDF。

- 前端：`HTML + CSS + JS`（单页，无需构建）
- 后端：`Python` 标准库 `http.server`（核心**零第三方依赖**；仅新增的可选 QQ 机器人 `qq_bot.py` 依赖官方 `qq-botpy`）
- 端口：`0100`（即 `100`，编辑）与 `8424`（只读）
- 数据**只存服务器 JSON 文件**，页面不读写浏览器 localStorage（避免不同入口访问时数据冲突）

## 二、启动方法

```bash
cd History_Learning
python server.py
```

启动后会自动打开浏览器到 `http://127.0.0.1:100`。
若端口被占用，可临时改用其它端口：

```bash
# Windows PowerShell
$env:PORT="8000"; python server.py
```

> 需要 Python 3.x，核心服务无需安装任何包；仅当要启用 QQ 机器人时需 `pip install qq-botpy`（见上文）。
> 按 `Ctrl+C` 停止服务。
> 同一时间只运行**一个** server.py 实例，避免端口冲突与新旧代码混用。

### 局域网访问（其它设备）

默认监听 `0.0.0.0`（所有网卡），因此**同一局域网内的其它设备**也可以用
`http://<服务器IP>:100`（编辑）或 `http://<服务器IP>:8424`（只读）访问。
启动时控制台会打印本机可用的局域网地址（如 `http://192.168.x.x:100`）。

- 查看本机局域网 IP（Windows）：`ipconfig`
- 若其它设备访问不到，多为 **Windows 防火墙**拦了 Python 的入站，请在防火墙放行 Python（或 100 / 8424 端口）。
- 数据通过服务器 JSON 文件在端口间共享；只读端口(8424)只能查看/导出，不能改内容。

### 公网 IPv6 访问（需 AccessToken）

`100` 与 `8424` 现均为 **IPv6 双栈**监听。**纯公网 IPv6 访问必须携带有效 `AccessToken`**，
否则一律返回 403；`127.0.0.1` / 局域网 IPv4 / 回环 `::1` 维持免凭证访问。

- 访问方式（编辑端口示例）：
  `http://[公网IPv6]:100/?AccessToken=<Token>`
- 首次携带有效 Token 后，服务器会下发 `AccessToken` 的 **HttpOnly Cookie**（有效期=Token 剩余时长），
  后续页面及 `/api/*` 请求由浏览器自动携带，无需再加参数。
- 本机可能有**多个公网 IPv6**（如 WLAN 会分配多个），qqbot 会全部列出；用你真实网卡的那个即可。
  若某个地址确认不可用，可用环境变量 `SKIP_IPV6`（逗号分隔的地址/子串）将其剔除。
- 若返回 403，表示该 Token 无效/已过期/用途与端口不符——通过 QQ 机器人私聊「地址」重新获取后再访问。
- 手机/平板若与服务器**在同一局域网（同一 WiFi/网段）**，**直接用局域网 IPv4 免凭证最稳妥**（见上节）：
  只读 `http://192.168.x.x:8424/`、编辑 `http://192.168.x.x:100/`。同网段设备去访问**公网 IPv6** 时，
  可能因家用路由器「回环转发」间歇性报 `ERR_INVALID_HTTP_RESPONSE`——这是网络路径问题，**不是服务器故障**，
  改用局域网 IPv4 即可。公网 IPv6 + Token 通道用于你在**外出**（非本网络）时访问。
- 前提是你的网络分配了公网 IPv6 地址（`ipconfig` 里能看见 `2001:…`/`240e:…` 等非 link-local 地址），并放行防火墙。若没有公网 IPv6，则无法公网访问。

> 运行 `qq_bot.py` 逻辑后，可通过 **QQ 机器人私聊**获取上述 Token（见下节）。

### QQ 机器人分发访问凭证（qq_bot.py）

按 QQ 官方接入方式，用 `qq-botpy` SDK 连接 QQ 机器人，通过**私聊(C2C)**渠道安全分发访问凭证。
逻辑封装在独立文件 `qq_bot.py`，由 `server.py` 导入调用。

#### ① 安装依赖

```bash
pip install qq-botpy
```

#### ② 配置机器人凭证（推荐：设置页；兼容环境变量）

**推荐方式（配置外置，落库到 `settings.json`）**：启动服务后打开设置页
`http://127.0.0.1:100/settings.html`，在「QQ 机器人凭证」里填写 AppID / AppSecret 并保存，
保存后服务器自动重启机器人线程，无需重启服务。

**兼容方式（环境变量）**：也可在启动 `server.py` 前设置本机环境变量（首次生成 `settings.json` 时会自动带入）：

```powershell
# Windows PowerShell
$env:QQ_BOT_APPID="你的机器人AppID"
$env:QQ_BOT_SECRET="你的机器人AppSecret"
python server.py
```

> 机器人凭证在 QQ 开放平台注册后获得；SDK 内部先用 `AppID + AppSecret` 换取平台 Access Token 再连 WebSocket（官方推荐鉴权方式）。
> `settings.json` 一旦生成即为唯一权威来源（设置/配色 + 凭证都存这里）；设置页保存的凭证优先于环境变量。

#### ③ 使用

1. 在 QQ 里与机器人**单聊**（C2C）。
2. 发送文字「**地址**」。
3. 机器人私聊回复：服务端公网 **IPv6 地址**、**编辑端口(100)** 链接（Token 有效期 **10 分钟**）、**只读端口(8424)** 链接（Token 有效期 **1 小时**）。
4. 用返回的链接在公网访问；无 Token 的 IPv6 访问会被拦截。

#### ④ 凭证说明

- Token **每次指令都重新签发、随机生成且到期自动失效**，长度 **96 位十六进制**。
- Token **持久化到 `tokens.json`**：服务重启后仍在各自有效期内的 Token 依旧可用，不会因重启而集体失效（到期的 Token 自动清理）。
- 编辑端口(100)与只读端口(8424)的 Token **用途分开校验**，互不可混用。
- Token 有效期可通过环境变量调整：`EDIT_TOKEN_TTL`（默认 600 秒）、`READONLY_TOKEN_TTL`（默认 3600 秒）。
- 未配置 `QQ_BOT_APPID / QQ_BOT_SECRET`（`settings.json` 为空）时机器人不启动，IPv6 访问默认一律拦截，不影响本地/局域网使用。
- 此 Token 与 QQ 平台鉴权用的 Access Token 相互独立。

## 四、数据如何保存？

- **服务器 JSON 为唯一数据源**：时间轴数据在 `data.json`、问答数据在 `qa_data.json`、速查薄弱点在 `quickref_data.json`、全局设置（配色 + 机器人凭证 + 版本号）在 `settings.json`。页面**不写 localStorage**，刷新/换设备/换端口看到的都是同一份数据。
- **自动同步**：你的每次修改自动写入对应 JSON（由 `server.py` 提供接口），无需手动操作。
- **启动自动恢复**：后端启动时若某文件不存在会自动创建空骨架；页面打开时自动从服务器加载。
- **手动兜底**：页面上的「数据」弹窗提供 导出 JSON / 导入 JSON / 手动保存到服务器 / 从服务器加载，用于备份、分享、换设备。
- **自动备份**：每次向 JSON 写入**内容有变化**的新数据前，自动把旧版本备份到 `backups/`（命名 `data_YYYYMMDD_HHMMSS.json` / `qa_*.json` / `quickref_*.json` / `settings_*.json`），最多保留最近 30 份，超出自动删除最老的。误改/误导入后可从这里恢复。

### 数据文件一览

| 文件 | 内容 | 顶层结构 |
| --- | --- | --- |
| `data.json` | 时间轴（多文档） | `{"version":2,"docs":[...]}` |
| `qa_data.json` | 问答（文档 + 薄弱点） | `{"version":1,"docs":[...],"weakLists":[...]}` |
| `quickref_data.json` | 速查（人物/地点薄弱点列表） | `{"version":1,"weakLists":[...]}` |
| `settings.json`（首次启动自动生成） | 全局设置：配色 + QQ 机器人凭证 + 版本号（取代 `ui_config.json`） | `{"version":2,"appVersion":"v2.10","theme":"...","qqBot":{"appid":"...","secret":"..."}}` |
| `tokens.json`（运行后生成） | 访问凭证缓存 | `{token:{"exp":…,"purpose":"edit"|"readonly"}}` |

## 六、时间轴页（timeline.html）

### 1. 多时间轴文档（标签卡）

- 顶部标签卡一行可新建（＋）、切换、双击重命名、✕删除多个时间轴文档，数据相互独立。
- 至少保留一个文档；删除前会自动清理由其引发的悬空引用。
- 导入 JSON 时兼容旧版单文档格式（顶层直接含 `lanes`），自动包装为多文档格式。

### 2. 时间轴（横向 × 纵向）

- **横坐标 = 时间**：从左到右由古到今。
- **纵坐标 = 地理区域 / 文明**：每个横行一个文明；地域相近的可按时间先后排在**同一横行**（前后文明只要时间不重叠即可共行）。
- 事件框为圆角矩形；同一横行的事件之间用**箭头**连接（纯 CSS 线条 + ▸，箭头始终显示）。

### 3. 两种整体对齐方式（工具栏下拉切换）

- **等比缩放 (scale)**：严格按年份比例尺，x 坐标与年份成正比；相邻矩形之间保证不重叠并有足够空隙容纳箭头。
- **相对排列 (relative)**：**所有文明共享一条横轴，按时间先后全局排布**——保证不同文明的事件之间也有明确的先后顺序，相邻时间框之间施加固定最小间距，尽可能紧凑。
- 「每百年像素」下拉可调整等比模式的疏密：**数值越小整体越紧凑、箭头越短**。
- 画布宽度有安全上限（60,000px），防止超大时间跨度导致浏览器渲染问题。

### 4. 元素隐藏 / 显示（「👁 显隐」）

- 时间框、箭头：**始终显示**。
- 可独立开关：时间文字 / 事件框 / 事件文字 / 详细信息框 / 详细框标志符号 / 详细框文字。
- 文明行（「🏛 文明」面板取消勾选）：整行隐藏，**下方行自动补位，不留空白**；再次勾选即恢复。

### 5. 信息的添加 / 导入导出（「⚙ 数据」）

- **GUI 添加（逐条）**：点「🏛 文明」→ 添加文明/事件；编辑弹窗里 **详细信息采用“选类型 + 填内容”逐条添加**（普通文字 / 地点【】/ 人名（）/ 分点记忆），保存时自动套好标记。新增的“空文明”行在画布上会显示一个可点击的占位卡片（点击即可直接添加第一个事件）。
- **JSON 导入**：粘贴 JSON（格式见下文）覆盖当前数据；旧单文档格式自动兼容。
- **导出**：复制或下载为 `.json`（迁移、分享、备份）。
- **离线网页**：一键导出含全部时间轴文档的单文件 `.offline.html`，双击即可离线查看，无需服务器。

### 6. 打印 / 导出 PDF（「🖨 打印PDF」）

- 点击后调用浏览器打印服务（Windows 11 下可用“另存为 PDF”或金山/微软打印），**所见即所得**。
- 若时间轴较宽，建议在打印预览里选择**横向纸张**，并可用预览中自带的缩放（“适合页面宽度”）调整到单页或分页效果。

## 七、问答练习页（qa.html）

### 1. 导入 Markdown

- 「导入 md」粘贴或上传 Markdown 文档，自动解析为「单元 → 题目 → 答案」结构。
- 解析规则：
  - **单元标题**：一级标题 `# 第X单元`（页面会显示单元名，不直接作为题目）。
  - **题目**：仅**带编号的二级标题**才算题目，例如 `## 1、虎门销烟意义`、`3. ## 虎门销烟意义`。
  - **答案**：题目标题下的所有正文（含子标题/列表/表格）都属于该题答案，按 **Markdown 渲染**显示。
- 同一文档内允许多个单元，多道题目。

### 2. 练习交互

- 每题先显示题号与题目，点击「显示答案」按钮展开该题答案（支持 Markdown 加粗/标题/列表/表格渲染）。
- 工具栏支持**全部显示答案 / 全部隐藏答案**。
- **分页**：每页 10 / 20 / 30 条（默认 30，最多 30，防止移动端加载失败），可翻页。
- **星标薄弱点**：每题右侧 ⭐ 按钮，点亮后进入当前薄弱点列表；可新建/命名/切换/删除多条薄弱点列表，也可把某列表导出为 JSON、下次再导入回来针对性练习。
- **多文档标签卡**：上方标签卡切换不同文档（数据独立），＋新建空文档，双击重命名。

### 3. 数据管理

- 「⚙ 数据」弹窗：手动保存到服务器 / 从服务器加载 / 导出 JSON / 导入 JSON / 导出离线网页（`问答练习.offline.html`）。
- 全部数据存于服务器 `qa_data.json`，页面不写 localStorage。

### 4. 速查页（quickref.html）

- **用途**：从**地点 / 人物**逆向找出相关事件并记忆（看名想事）。
- **数据来源**：即时取自时间轴 `data.json`（通过 `/api/load`）；顶部「数据来源」可勾选**一个或多个**时间轴文档，并选择**人物或地点**之一。同一名字跨文档的实体自动合并。
- **信息一览**：每个「人物/地点」一列，完整列出其所有相关事件（事件框样式与时间轴一致：时间框 + 事件框 + 详情框）；按实体分页（10/20/30）；每个实体可「展示事件 / 收起事件」，上方可**全部展示 / 全部收起**。
- **主动学习**：一页一个实体，先显示名字，点「点击展示相关事件」才展示其全部相关事件；可**顺序**或**随机**（`🔀 重抽`）抽选，上一/下一个切换。
- **薄弱点**：实体右侧 `★` 加入当前薄弱点列表，列表存服务器 `quickref_data.json`；可新建/切换/重命名/删除/导出/导入；选中某列表后只查看该列表内实体（跨文档）。
- **打印 PDF**：点「🖨 打印PDF」把**当前筛选下全部实体**按「信息一览」排版（随当前展开/收起状态）生成后调用系统打印；打印时隐藏侧边栏/工具条/星标/分页，尽量**不分页**。
- **保存离线**：可导出含时间轴来源数据 + 薄弱点数据的单文件 `.offline.html`。
- 速查页自身**不修改**时间轴数据（只新增/更新 `quickref_data.json`）。

## 八、JSON 数据格式说明

### 1. data.json（时间轴，多文档）

```jsonc
{
  "version": 2,                                  // 多文档格式版本号
  "docs": [
    {
      "id": "doc1a0aa0f8d5a7cd31",               // 文档唯一标识
      "name": "世界历史 九年级上册 时间线",        // 标签卡上显示的名字
      "created": "2026-09-16 19:52",             // 创建时间

      "globalOptions": {
        "layout": "scale",                       // "scale"（等比）或 "relative"（相对最小间距）
        "pxPer100": 30,                          // 等比模式下每 100 年对应的像素宽度
        "theme": "parchment",                    // 仅 "parchment" | "ocean" | "forest" | "mono"
        "show": {                                // 元素显隐开关（true=显示）

          "name": "古代埃及",          // 文明名称（显示在每横行左侧标签）
          "visible": true,           // false 表示整行隐藏（隐藏的行会补位，不留空白）
          "color": null,             // 可选：行标签颜色（如 "#9c3"），null 用默认

              "startDay": null,                  // 可选：起始日（1-31；缺省=1日）
              "endYear": -3100,                  // 结束年份（数值；=起点即单点；时间段则为其右边界）

              "endDay": null,                    // 可选：结束日（1-31；缺省=1日）
              "eventText": "埃及初步实现统一",     // 事件文字
              "details": [                       // 详细信息，数组，每个元素一行字符串
```

> 旧版单文档格式（`{"version":1,"title":...,"lanes":[...]}`）会被后端/前端**自动迁移**为多文档格式并写回，数据不丢失。

### 时间 (timeText / startYear / endYear / 月 / 日)

- 时间表示方式：`XX世纪`、`XXX年`、`XXX年M月D日`，均支持**公元前 / 公元**。
- 定位用的是数值 `startYear` / `endYear`，**公元前一律用负数**：
  - 公元前 3100 年 → `-3100`
  - 公元前 21 世纪 → 起点 `-2099`（-21×100+1），终点 `-2000`
  - 公元 476 年 → `476`，公元 1 世纪 → `1 ~ 100`
- **月 / 日（可选）**：如需精确到月日，额外填写 `startMonth`/`startDay`（及结束端的 `endMonth`/`endDay`），1-12 月 / 1-31 日；留空视为该年 1 月 1 日。
  排序与等比定位会把月日换算成连续数值（年 + 月/12 + 日/365），同一年内不同月日也会区分先后。
- `timeText` 是**给人看**的原文（如“公元前3100年前后”、“公元1949年10月1日”），与数值分开存储，二者不必一致。
- 页面新增事件弹窗里有「↗ 从上方文字自动算出年月日并填入」按钮，可自动把“公元前N世纪 / N世纪 / 公元前N年 / N年 / 公元前N年M月D日 / N年M月D日”换算成数值与月日填入。

#### 排序与定位规则（start / end 的具体影响）

每个事件会换算出一个**起始时刻**与**结束时刻**（连续数值 = 年 + 月/12 + 日/365，公元前为负数）：

- **起始时刻 = `startYear`（+ `startMonth`/`startDay`）**：决定事件**排在哪**。
  - 所有排序（文明内左右顺序、跨文明的时间先后、等比/相对两种布局的横向位置）都以**起始时刻**为准，起始早的在前、在左。
- **结束时刻 = `endYear`（+ `endMonth`/`endDay`）**：决定事件**跨多长**。
  - **单点事件**（`endYear` 留空）：结束时刻 = 起始时刻，时间跨度为零，事件框按内容宽度显示。
  - **时间段事件**（`endYear` 有值）：等比布局中事件框宽度 ≈ (结束时刻 − 起始时刻) × 每百年像素；若该跨度对应的像素小于内容实际宽度，则以内容宽度为准（此时结束时刻只影响“时间上跨到哪”，不影响框宽）。
- **范围与坐标轴**：画布时间范围取所有事件中 起始/结束时刻 的最小值（向下取整）到最大值（向上取整），坐标轴刻度按整年绘制。
- **相对排列的分组**：起始时刻**完全相同**的事件共享同一横坐标、竖直对齐；只要起始时刻不同（哪怕同年不同月日）就依次右移错开。
- 若 `startYear` 与 `endYear` 大小写反了（结束早于开始），等比布局会按两者最小值为左、最大值为右绘制，不会画错方向。

### 详细信息标记（可任意组合在同一行）

| 格式 | 含义 | 示例 |
| --- | --- | --- |
| `【地点】` | 地点 | `【尼罗河流域】` |
| `（人名）` | 人名 | `（汉谟拉比）` |
| `_分点_、_分点_` | 分点记忆（若干下划线项，用顿号分隔）| `_中央集权_、_文字_、_多神_` |

- 三者可在同一行/同一条信息里任意组合，例如：
  `【两河流域】（汉谟拉比）_法典_、_集权_`
- “分点记忆”由**顿号 `、` 分隔的若干个下划线项**构成，每个下划线项用 `_内容_` 包裹（存储格式）；但在**编辑弹窗里用“逐条类型化”方式录入**（选类型+填内容），保存时自动套好上述标记，你无需手写符号。导入的组合式 JSON 会被自动拆分回逐条类型。

| 方法 | 路径 | 说明 | 只读端口(8424) |
| --- | --- | --- | --- |
| GET | `/api/load` | 读取时间轴数据 `data.json` | ✅ |
| GET | `/api/qa/load` | 读取问答数据 `qa_data.json` | ✅ |
| GET | `/api/quickref/load` | 读取速查薄弱点数据 `quickref_data.json` | ✅ |

| GET | `/api/health` | 健康检查 | ✅ |
| POST | `/api/save` | 保存时间轴数据 | ❌ 403 |

> **IPv6 访问门禁**：以上所有接口在**纯公网 IPv6** 来源下都要求携带有效 `AccessToken`

> 编辑端口(100)要求**编辑用途** Token、只读端口(8424)要求**只读用途** Token，两者互不可混用；
> Token 由 QQ 机器人私聊「地址」指令签发（见上文）。

## 十、排障

| 现象 | 处理 |
| --- | --- |
| 浏览器打不开 | 确认先运行 `python server.py`，地址为 `http://127.0.0.1:100`（含端口号） |
| 端口被占用 / 页面还是旧版 | 先停止旧进程，确保**只有一个** `python server.py` 在运行，再启动 |
| 「保存到服务器」失败 | 该功能依赖后端，请通过 `server.py` 访问页面（而非直接用文件双击打开 html） |
| 页面改动后没生效 | 服务端已禁用缓存，刷新（Ctrl+F5）即可；若改了 server.py 需重启服务 |
| 导入导出的 JSON 无法用 | 时间轴检查顶层是否含 `docs` 数组（旧 `lanes` 格式会自动迁移）；问答检查是否含 `docs`/`weakLists` |
| 打印内容过宽被切页 | 打印预览中把纸张设为横向后，再选缩放“适合页面宽度” |
| 想恢复被覆盖的数据 | 查看 `backups/` 下按时间命名的备份文件，直接改回原名（如 `data.json`）即可 |
