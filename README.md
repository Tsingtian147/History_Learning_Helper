# 1. 项目整体介绍

## 1.1 开发背景

「世界历史 九年级上册」涵盖了从**史前人类**到**近代前夕**跨度几千年、跨越亚欧非美多个文明的大体量知识点。学习过程中普遍面临三大痛点：

- 🕰️ 知识点**散落在教材各课**，缺乏了一条贯穿全局的时间主线；
- 🌍 多文明（埃及、两河、印度、希腊、罗马、阿拉伯、西非、美洲……）**并存在不同时空**，彼此先后与联系难以一眼看清；
- 📝 背了就忘，缺少把 **「事件 → 地点 / 人物 / 意义」** 联系起来的**主动回忆**训练工具。

本项目从「一张能滚动、能缩放、能自由编辑的**历史时间轴**」出发，逐步扩展为**时间轴 + 问答 + 速查**三位一体的学习平台，并支持将数据带在身边（局域网 / 公网）随时复习。

## 1.2 解决的问题

| 痛点             | 本项目的解法                                        |
| -------------- | --------------------------------------------- |
| 历史时间线混乱        | **多文明并行横轴**，按时间先后排列，同一文明内用箭头串联                |
| 文明纵跨几千年，浏览器易卡死 | 画布宽度**上限 60,000px**，等比/相对两种布局可控疏密             |
| 一大堆历史名词记不住     | **速查页**：从「地点 / 人物」反查事件，主动回忆式学习                |
| 知识点要学会「做题」     | **问答页**：导入 Markdown，自动拆成「单元→题→答」，先作答再看答案      |
| 换了设备数据就乱       | **服务器 JSON 为唯一数据源**，页面不写浏览器 localStorage，多端一致 |
| 误改 / 误导入导致数据丢失 | 每次写入前**自动备份**旧版，最多保留 30 份，可随时回滚               |
| 想在外面用手机复习      | 公网 IPv6 + **QQ 机器人安全分发访问凭证**，免公网 IP 配置        |
| 不想装一堆依赖        | 后端 **纯 Python 标准库**，前端零框架零构建，一条命令跑起来          |

## 1.3 实现方式

```text
┌──────────────────────────── 前端（static/）────────────────────────────┐
│  index.html        主页（入口 / 侧边栏导航）                              │
│  timeline.html     时间轴 · 多文档标签页 · 双布局 · 显隐开关              │
│  qa.html           问答练习 · Markdown导入 · 分页 · 薄弱点               │
│  quickref.html     速查 · 地点/人物反查事件 · 主动学习 · 打印PDF          │
│  settings.html     全局设置 · QQ机器人凭证 · 全局配色 · 版本号            │
└─────────────────────────────┬──────────────────────────────────────────┘
                              │ HTTP (GET 静态页 + /api/* JSON 接口)
┌─────────────────────────────▼──────────────────────────────────────────┐
│  后端 server.py（Python 标准库 http.server）                            │
│  · 双端口：0100(编辑) / 8424(只读)   · IPv6 双栈 + 0.0.0.0 监听          │
│  · Token 凭证门禁（仅公网 IPv6）     · 自动备份 + 原子写 + 旧版自动迁移   │
│  · 可选 qq_bot.py：QQ 机器人私聊分发访问凭证                             │
└─────────────────────────────┬──────────────────────────────────────────┘
                              │ 文件系统
        ┌────────────────────┼─────────────────────┐
        ▼                    ▼                     ▼
   data.json           qa_data.json           settings.json
   (时间轴多文档)        (问答+薄弱点)           (配色/凭证/版本)
             └─ backups/ 自动备份目录（最多 30 份）
```

- **前端**：原生 `HTML + CSS + JS`，无需 npm / 打包，刷新即用；
- **后端**：Python 标准库 `http.server` 的 `ThreadingHTTPServer`，**零第三方依赖**（仅可选 QQ 机器人需 `qq-botpy`）；
- **网络**：IPv6 双栈（`AF_INET6` + `IPV6_V6ONLY=0`）+ 绑定 `0.0.0.0`，同一端口同时服务**局域网 IPv4** 与**公网 IPv6**；
- **安全**：公网 IPv6 访问必须携带平台签发的 `AccessToken`（URL 参数或 HttpOnly Cookie），只读/编辑端口 Token 用途隔离；
- **存储**：读写分离，只读端口在**服务端强制拒绝**所有写入接口。

## 1.4 突出优势

✨ **三大硬核技术亮点**，也正是本项目区别于普通「静态网页」的地方：

| 能力                   | 技术实现                                  | 带来的价值                             |
| -------------------- | ------------------------------------- | --------------------------------- |
| 🚀 **零部署零依赖**        | 纯 `http.server` 标准库，前端零构建             | 任何装了 Python 3 的机器一条命令即可运行，适合学习/演示 |
| 🔐 **读写隔离双端口**       | 编辑端口 `100` 可写、只读端口 `8424` 只读，服务端强制拒绝写 | 把「展示版」和「编辑版」分开，误操作零风险，便于对外分享      |
| 🌏 **免公网 IP 也能远程访问** | IPv6 双栈 + QQ 机器人私聊分发一次性 Token         | 人在外面用手机也能看，无需购买域名 / 配置路由器端口映射     |
| 🧠 **AI 一键生成数据**     | 标准化的 JSON 格式 + 现成提示词模板                | 把课本 / 手写笔记扔给 AI，直接得到可用数据，内容生产门槛极低 |
| 🛡️ **数据永不丢**        | 内容变化才备份 + 原子写 + 旧版自动迁移                | 误改误导可回滚，跨版本升级不丢失历史数据              |

# 2. 具体页面说明

应用内置 5 个页面，通过左侧**侧边栏**相互切换（悬停展开文字）：

| 图标  | 页面   | 地址               | 功能亮点                            |
| --- | ---- | ---------------- | ------------------------------- |
| 🏠  | 主页   | `/`              | 整体入口，预留主页占位                     |
| 🕰️ | 时间轴  | `/timeline.html` | 多文明并行、两种布局、显隐开关、多时间轴文档、打印PDF    |
| 💬  | 问答练习 | `/qa.html`       | Markdown 导入、单元/题目/答案三级结构、分页、薄弱点 |
| 🔍  | 速查   | `/quickref.html` | 地点/人物反查事件、主动学习模式、薄弱点、打印PDF      |
| ⚙️  | 设置   | `/settings.html` | QQ 机器人凭证、全局配色、版本号               |

### 🕰️ 时间轴页（timeline.html）

- **横向 × 纵向**：横坐标是时间（左古右今），纵坐标是文明/地区，每个横行一个文明，地域相近可共行；
- **两种整体对齐**：
  - `等比缩放 (scale)`：严格按年份比例尺定位；
  - `相对排列 (relative)`：所有文明共享一条横轴，保证跨文明的先后顺序，整体更紧凑；
  - 支持「每百年像素」调节疏密；画布宽度上限 **60,000px**；
- **元素显隐**：时间文字 / 事件框 / 事件文字 / 详情框 / 详情标志 / 详情文字 均可独立开关；整行文明可隐藏并自动补位；
- **多时间轴文档**：顶部标签卡可新建、切换、重命名、删除多个时间轴，数据相互独立；
- **信息详情**：普通文字 / `【地点】` / `（人名）` / `_分点_` 等类型化标记逐条录入；
- **数据面板**：导入 / 导出 JSON、手动保存 / 从服务器加载；
- **导出离线**：一键生成 `.offline.html` 单文件，双击即看，无需服务器；
- **打印 PDF**：所见即所得，支持横向纸张 + 适合页面宽度。

### 💬 问答练习页（qa.html）

- **Markdown 导入**：粘贴 / 上传 Markdown，自动解析为「**单元 → 题目 → 答案**」；
  - 单元标题：一级标题 `# 第X单元`；
  - 题目：**仅带编号的二级标题**，如 `## 1、虎门销烟意义`；
  - 答案：题目标题下所有正文，按 **Markdown 渲染**（加粗 / 列表 / 表格）；
- **先作答再看答案**：每题一个「显示答案」按钮，支持**全部显示 / 全部隐藏**；
- **分页**：每页 10 / 20 / 30 条（默认 30，上限防移动端卡死）；
- **薄弱点**：⭐ 星标题目形成薄弱点列表，可新建 / 切换 / 导出 / 导入，针对性重练；
- **多文档 + 离线导出**：多文档标签卡、单文件 `.offline.html`。

### 🔍 速查页（quickref.html）

- **数据来源**：即时取自时间轴 `data.json`，可勾选**一个或多个**时间轴文档，选择**人物**或**地点**维度；跨文档同名实体自动合并；
- **信息一览**：每个「人 / 地」一列，完整列出其全部相关事件，按实体分页（10/20/30）；
- **主动学习**：一页一个实体，先显名再点开事件，支持**顺序 / 随机**抽选，实现记忆提取训练；
- **薄弱点**：★ 标记进入列表，可切换 / 重命名 / 导出 / 导入；
- **打印 PDF / 导出离线**。

# 3. 快速开始

> 全程约 **10 分钟**即可跑起来并让手机访问。下面按步骤一步步来。

## 3.1 环境准备

| 准备项            | 说明                     | 检查命令               |
| -------------- | ---------------------- | ------------------ |
| **Python 3.x** | 后端运行环境，**无需安装任何依赖包**   | `python --version` |
| **浏览器**        | 任意现代浏览器（Chrome / Edge） | —                  |

> 核心服务零依赖；**仅当**要启用 QQ 机器人远程访问时才需要 `pip install qq-botpy`（见 3.5）。

## 3.2 启动服务

把项目（含 `server.py`、`static/`、`data.json`）放到任意目录，然后：

```bash
cd History_Learning
python server.py
```

启动后会自动打开浏览器到 `http://127.0.0.1:100`。控制台会打印：

```
世界历史学习 · 时间轴应用已启动
  本机 编辑端口(读写)：http://127.0.0.1:100/
  本机 只读端口(查看)：http://127.0.0.1:8424/
  局域网访问（其他设备）：
     编辑：http://192.168.x.x:100/    只读：http://192.168.x.x:8424/
```

- **编辑端口 `100`**：可查看 / 添加 / 修改 / 导入导出；
- **只读端口 `8424`**：只能查看 / 导出 / 保存离线网页，**无法修改内容**；
- 按 `Ctrl+C` 停止服务；
- ⚠️ **同一时间只运行一个 `server.py` 实例**，避免端口冲突与新旧代码混用。

**端口被占用了？** 用环境变量临时换端口：

```powershell
# Windows PowerShell
$env:PORT="8000"; python server.py
# 只读端口默认 8424，也可改：
$env:READ_ONLY_PORT="9000"; $env:PORT="8000"; python server.py
```

## 3.3 局域网访问（其它设备）

服务默认监听 `0.0.0.0`（所有网卡），**同一 WiFi 下的手机 / 平板直接用局域网 IPv4 免凭证访问最稳妥**：

- 只读：`http://192.168.x.x:8424/`
- 编辑：`http://192.168.x.x:100/`

> 查看本机局域网 IP（Windows）：`ipconfig`。
> 若其它设备访问不到，多为 **Windows 防火墙**拦截了 Python 入站，请放行 Python（或 100 / 8424 端口）。

## 3.4 QQ 机器人官方注册入口

要实现在**公网（外出）**访问，需要申请一个 **QQ 机器人**，用它私聊分发访问凭证（免公网 IP / 端口映射）。

**官方注册入口：**

> 🔗 **QQ 机器人开放平台：https://q.qq.com/** （点击直接进入）

简要流程：

1. 打开 https://q.qq.com/ ，使用你的 **QQ 账号登录**（建议用常用 QQ）；
2. 登录后进入**开放平台控制台**，按引导完成**开发者实名认证**；
3. 在「机器人管理」中**创建机器人应用**；
4. 创建成功后，在应用详情页拿到两个关键凭证：
   - **AppID** —— 机器人唯一标识；
   - **AppSecret** —— 用于换取平台 Access Token（**请妥善保管，切勿公开**）；
5. 按平台引导将机器人**上架并设为「私聊可用」**（本项目的凭证分发依赖私聊 / C2C 渠道）。

> 官方 SDK 与开发文档：🔗 **https://q.qq.com/wiki/** （qq-botpy / API 说明）。
> 本项目使用的 `qq-botpy` SDK：🔗 **https://github.com/TencentQQBot/qq-botpy**

## 3.5 配置 QQ 机器人

拿到 AppID / AppSecret 后，二选一写入配置：

**方式 A：网页设置页（推荐，无需重启）**

1. 打开本项目编辑页 `http://127.0.0.1:100/settings.html`；
2. 在「QQ 机器人凭证」填入 AppID / AppSecret 并保存；
3. 保存后服务器**自动重启机器人线程**，立即生效。

**方式 B：环境变量（首次启动自动带入）**

```powershell
# Windows PowerShell
$env:QQ_BOT_APPID="你的机器人AppID"
$env:QQ_BOT_SECRET="你的机器人AppSecret"
python server.py
```

> 需先安装：`pip install qq-botpy`。
> 凭证最终持久化到 `settings.json`（设置页保存的优先于环境变量）。
> ⚠️ **AppSecret 为机密信息，请勿分享。**

## 3.6 通过 QQ 私聊获取公网访问地址

1. 在 QQ 里搜到你的机器人，与其**单聊（C2C）**；
2. 发送文字：**地址**；
3. 机器人私聊回复一段文本，包含：
   - 服务端**公网 IPv6 地址**（本机可能有多个，选你真实网卡的）；
   - **编辑端口 `100`** 链接（内嵌 Token，有效期 **10 分钟**）；
   - **只读端口 `8424`** 链接（内嵌 Token，有效期 **1 小时**）；
4. 直接点开对应链接即可在公网访问。

> **Token 每次指令都重新生成**，随机 96 位十六进制，到期自动失效，并持久化到 `tokens.json`（服务重启后未到期的仍可用）。

## 3.7 公网 IPv6 访问

访问链接形如：

```
http://[公网IPv6]:100/?AccessToken=<Token>     # 编辑
http://[公网IPv6]:8424/?AccessToken=<Token>    # 只读
```

- 首次携带有效 Token 访问后，服务器会下发 **HttpOnly Cookie**（有效期 = Token 剩余时长），后续页面与 `/api/*` 请求自动携带，**无需再加参数**；
- **无 Token 的纯公网 IPv6 访问一律返回 403**；本机 `127.0.0.1` / 局域网 IPv4 / 回环 `::1` 免凭证；
- 编辑端口需**编辑用途** Token，只读端口需**只读用途** Token，互相不可混用；
- 若收到 403，说明 Token 无效 / 过期 / 用途不符，用 QQ 私聊「地址」重新获取；
- 网络分配了公网 IPv6 地址（`ipconfig` 可见 `2001:` / `240e:` 等）且防火墙放行才可公网访问；
- 若本机多个 IPv6 混入虚拟网卡，可用环境变量剔除：`$env:SKIP_IPV6="2409:xxxx"`

> 💡 **同一 WiFi 下优先用局域网 IPv4 免凭证访问**（见 3.3）。同网段设备访问公网 IPv6 可能因家用路由器「回环转发」间歇报错，这是网络路径问题，不是服务器故障。

# 4. 数据格式详解

本项目数据**只存服务器 JSON 文件**，页面不写浏览器 `localStorage`，因此**同一份数据在所有入口 / 设备上完全一致**。

## 4.1 data.json —— 时间轴多文档格式

> 顶层 `version: 2`，多文档结构。若读到旧版单文档格式（顶层直接含 `lanes` 而无 `docs`），后端会**自动迁移**为多文档格式并写回，数据不丢失。

```jsonc
{
  "version": 2,                            // 固定为 2（多文档格式版本号）
  "docs": [
    {
      "id": "docxxx",                      // 文档唯一标识
      "name": "世界历史 九年级上册 时间线",    // 标签卡上显示的名字
      "created": "2026-09-16 19:52",       // 创建时间
      "title": "世界历史 九年级上册 时间线",  // 页面顶部大标题
      "globalOptions": {
        "layout": "scale",                 // "scale"(等比) 或 "relative"(相对最小间距)
        "pxPer100": 30,                    // 等比模式下每 100 年对应的像素宽
        "theme": "parchment",              // 仅 parchment|ocean|forest|mono
        "customColors": { "bg": "#f5efe0", /* 可选：自定义配色 */ },
        "show": {                          // 元素显隐开关(true=显示)
          "timeText": true,     // 时间框文字
          "eventBox": true,     // 事件框
          "eventText": true,    // 事件框文字
          "detailBox": true,    // 详细信息框
          "detailSymbol": true, // 详细信息标志符号
          "detailText": true    // 详细信息文字
        }
      },
      "lanes": [
        {
          "id": "lane_egypt",              // 文明行唯一标识
          "name": "古埃及",                 // 文明名（显示在行左侧）
          "visible": true,                 // false 整行隐藏(自动补位)
          "color": null,                   // 可选：行标签颜色，null 用默认
          "events": [
            {
              "id": "e_egypt_1",            // 事件唯一标识
              "timeText": "公元前3100年前后",// 时间框显示原文(给人看)
              "startYear": -3100,           // 起始年(公元前负数)
              "startMonth": null,           // 可选：起始月 1-12
              "startDay": null,             // 可选：起始日 1-31
              "endYear": -3100,             // 结束年(=起点即单点事件)
              "endMonth": null,             // 可选：结束月
              "endDay": null,               // 可选：结束日
              "eventText": "埃及初步实现统一",// 事件名
              "details": [                  // 详细信息(数组，每元素一行)
                "【尼罗河流域】（那尔迈）_中央集权_、_文字_"
              ]
            }
          ]
        }
      ]
    }
  ]
}
```

**字段速查表（event）：**

| 字段                        | 类型       | 必填   | 说明                     |
| ------------------------- | -------- | ---- | ---------------------- |
| `id`                      | string   | ✅    | 事件唯一标识                 |
| `timeText`                | string   | ✅    | 时间框显示原文（如「公元前3100年前后」） |
| `startYear`               | number   | ✅    | 起始年数值，**公元前用负数**       |
| `endYear`                 | number   | ✅    | 结束年数值，等于起点即单点事件        |
| `startMonth` / `startDay` | number   | null | ❌                      |
| `endMonth` / `endDay`     | number   | null | ❌                      |
| `eventText`               | string   | ✅    | 事件名                    |
| `details`                 | string[] | ✅    | 详细信息行（含类型化标记）          |

## 4.2 时间表示规则

- **数值与原文分离**：`timeText` 是给人看的原文，`startYear`/`endYear` 是计算用的数值，二者不必完全一致；
- **公元前一律用负数**：

| 时间         | startYear | endYear |
| ---------- | --------- | ------- |
| 公元前 3100 年 | `-3100`   | `-3100` |
| 公元前 21 世纪  | `-2099`   | `-2000` |
| 公元 476 年   | `476`     | `476`   |
| 公元 1 世纪    | `1`       | `100`   |

- **月 / 日（可选）**：`startMonth`/`startDay`（及结束端），1-12 / 1-31；留空视为该年 1 月 1 日。排序与等比定位会把「年 + 月/12 + 日/365」换算成连续数值，同年不同月日也能区分先后；
- **排序 / 定位规则**：
  - 起始时刻决定「排在哪」（文明内左右顺序、跨文明先后、横向坐标）；
  - 结束时刻决定「跨多长」（时间段事件的框宽 ≈ 跨度 × 每百年像素，过窄则以内容宽度为准）；
  - 画布时间范围取所有事件 起止时刻 的最小/最大值，坐标轴按整年绘制。

## 4.3 详细信息类型化标记

同一行信息内可自由组合：

| 格式          | 含义             | 示例                 |
| ----------- | -------------- | ------------------ |
| `【地点】`      | 地点             | `【尼罗河流域】`          |
| `（人名）`      | 人物             | `（汉谟拉比）`           |
| `_分点_、_分点_` | 分点记忆（顿号分隔下划线项） | `_中央集权_、_文字_、_多神_` |

组合示例：`【两河流域】（汉谟拉比）_法典_、_集权_`

> 在编辑弹窗里用「选类型 + 填内容」逐条录入，保存时自动套好标记，**无需手写符号**；导入的组合式 JSON 会被自动拆分回逐条类型。

# 6. 远程访问安全架构

```text
       外来设备（公网）
        │  仅公网 IPv6 可达
        ▼
┌───────────────────────────────────────────────┐
│  server.py  (IPv6 双栈 + 0.0.0.0)             │
│                                              │
│  GET 进入 → 判“纯公网 IPv6”？                │
│     ├─ 否(本地/局域网) → 放行(免凭证)          │
│     └─ 是 → 校验 AccessToken:                │
│          ├─ 有效 → 下发 HttpOnly Cookie → 放行 │
│          └─ 无效/过期 → 403                   │
└───────────────▲──────────────────────────────┘
                │ 私聊「地址」指令签发 Token
      ┌─────────┴─────────┐
      │   QQ 机器人(qq_bot.py) │
      └───────────────────┘
```

- **双重安全**：公网必须 QQ 机器人私聊取得 Token，编辑 / 只读端口**用途隔离**；
- **Token 一次性**：随机生成、到期自动失效、持久化到 `tokens.json`；
- **读写分离**：只读端口从服务端拦截所有写接口，适合长期 / 公开摆放；
- **无需公网 IP / DDNS / 端口映射**：依赖公网 IPv6 + 本机双栈监听。

# 7. 常见问题排障

| 现象                                | 处理                                                             |
| --------------------------------- | -------------------------------------------------------------- |
| 浏览器打不开                            | 先运行 `python server.py`，地址必须带端口 `http://127.0.0.1:100`          |
| 页面还是旧版                            | 确保**只有一个** `python server.py` 在运行，再重启；改动后 `Ctrl+F5` 硬刷新        |
| 「保存到服务器」失败                        | 该功能依赖后端，请通过 `server.py` 访问页面，不要双击 html 文件                      |
| 导入 JSON 报错                        | 时间轴检查顶层含 `docs` 数组（旧 `lanes` 格式会自动迁移）；问答检查含 `docs`/`weakLists` |
| 打印过宽被切页                           | 打印预览选**横向纸张** + 缩放「适合页面宽度」                                     |
| 公网访问返回 403                        | QQ 私聊「地址」重新获取 Token（可能过期 / 用途不符）                               |
| 手机访问报 `ERR_INVALID_HTTP_RESPONSE` | 同 WiFi 下改用**局域网 IPv4** 免凭证访问（见 3.3）                            |
| 想恢复被覆盖的数据                         | 到 `backups/` 找到时间命名的备份，改名（如 `data.json`）替换即可                   |

# 8. 数据安全与版本管理

- **服务器 JSON 为唯一数据源**：时间轴 `data.json`、问答 `qa_data.json`、速查薄弱点 `quickref_data.json`、设置 `settings.json`；页面不写 `localStorage`；
- **自动备份**：写入**内容有变化**的新数据前，自动把旧版备份到 `backups/`（命名 `数据前缀_时间戳.json`），**最多保留 30 份**，超出删除最老的；
- **原子写**：先写临时文件再 `os.replace` 替换，防止写一半损坏；
- **旧版自动迁移**：旧单文档 `data.json` 会在启动时自动迁移为多文档格式并写回；
- **版本归档**：`Release/` 目录按版本快照保存每个阶段的可运行版本，便于回退与对比。
